## Deviations from the written spec (deliberate, already tested)

1. **Claim status.** One branch confirmed and the other still in flight is `pending`, not `partial`.
   `partial` requires one confirmed and one failed, per `data-model.md` and `http-api.md`. T139's
   wording ("a single confirmed branch yields partial") is looser than the specs; the specs win.
2. **`NoActiveLoan` reverts.** The docs say the runId is consumed in that path, but a revert cannot
   persist the flag. Safety holds anyway: nothing was paid, and a retry finds nothing again.
3. **Cancel-after-liquidation.** A policy cancelled in a block *after* the liquidation block still
   gets relief. Taken literally, the documented check order (`status == Active` before comparing
   `cancelledAtBlock`) makes the FR-014 carve-out unreachable.
4. **`policies_mirror.lltv`.** Added to `api/src/db/migrations/001_init.sql`; the indexer needs it to
   compute the fee. Migration 001 had never been applied anywhere, so it was edited in place instead
   of adding a 002.
5. **Receipt fields the events do not carry.** `split.*` stores the dispatched limits derived from
   the fee and mirrored share (on-chain caps are not separately observable), and `healthBefore` is
   derived as `healthAfter * debtAfter / (debtAfter + spent)` because `ReliefApplied` carries only
   the after-values. Actual paid amounts come from the branch events.
6. **Lasna indexing.** The indexer also reads `CallbackRequest` from the reactive contract, which
   T132's six-event list does not mention; without it the receipt cannot show the dispatch tx.
7. **viem `authorizationList`.** viem 2.57's read parameters require the EIP-7702 field. Read-only
   clients pass `authorizationList: undefined` with a comment. Do not remove it without checking.
8. **`make seed`/`make crash1`** now name their contract explicitly, `make fund-vault` exists for
   the Unichain reserve, and the stale `crash2` target was removed until Phase 4 adds `Crash2`.

## Gotchas that already cost time

- **Dual contracts per script file.** `forge script` needs `Script.s.sol:ContractName` when a file
  holds two contracts. Affected: `DeployBase` (`:DeployBase`, `:DeployPool`), `Wire` (`:Wire`,
  `:WireRegistry`), `SeedMarket` (`:SeedMarket`, `:FundClaimVault`).
- **Local anvil reactive deploy.** `DeployReactive` reverts with "call to non-contract address"
  unless `MockSystemContract` is etched at `0x8888888888888888888888888888888888888888` via
  `anvil_setCode`.
- **Morpho `Liquidate` topics.** Borrower is **topic3** (`id`, `caller`, `borrower`).
  `specs/001-second-wind/contracts/reactive-contract.md` still says topic2 — the doc is stale, the
  code and the tests follow Morpho. Fix the doc when convenient.
- **Test helper order.** Call `vm.expectRevert` *before* `vm.prank`. Errors with arguments need the
  full `abi.encodeWithSelector(...)`; a bare selector does not match.
- **`MockSystemContract` naming.** The callback struct is `CallbackRecord` (the event
  `CallbackRequest` would collide).
- **Web TypeScript** is pinned to `~5.9`; the scaffold's TS 7 breaks `typescript-eslint`.
  `tsconfig.app.json` uses project references, so run `npm run typecheck` (`tsc -b`), not bare
  `tsc --noEmit`.
- **API tests use an in-memory query double** (`api/test/utils/memory-db.ts`). Add methods there
  when a new query shape is introduced; do not swap it for a real database in unit tests.
- **`forge fmt`** is configured at 120 columns; run it after editing Solidity or `--check` fails.

## Architecture invariants not to break

- `CoveragePool` and `ClaimVault` have no `withdraw`, no `pause`, no upgrade path; the cash recipient
  is fixed at registration and never read from the payload.
- `runId = keccak256(abi.encode(chainId, txHash, logIndex))`; both branches must share it.
- The reactive contract is revert-free on data it does not control; every guard returns early.
- `isCoverable` / `reliefRemaining` come from chain; the API's cache is disposable and replayable.
- The reactive contract's `reliefUsed` / `cashPaid` are mirrors advanced by `ReliefApplied` /
  `ClaimPaid`, with in-flight amounts held in `reliefReserved` / `cashReserved`.
